===========================================================================
 Split-Screen Multiplayer for
 Harry Potter and the Prisoner of Azkaban (PC, EA/KnowWonder 2004)
 Technical prototype - Windows
===========================================================================

WHAT IT DOES
  Adds N-way vertical split-screen to a game that shipped with all
  split-screen support stripped out of its binaries. Each strip follows a
  different character and players 2..N are directly controllable.

  Nothing is recompiled and no game file is modified. The mod is a proxy
  d3d8.dll that loads with the game, hooks the renderer, and drives the
  engine's own DrawPortal once per player.


V54 COOPERATIVE SUSTAINED CAST (IN-GAME TESTING PENDING)
  This is a general fallback for real HP3 objects that require Harry,
  Hermione and Ron to keep casting together. It is NOT a Pixie-well-only
  solution, does not complete a minigame directly, and never calls generic
  Trigger(), synthetic Touch(), repeated spell impacts, or a guessed target
  property.

  SAFETY / ONE-TIME PER-LEVEL CALIBRATION:
    Before P2/P3 can use the fallback, leave the split OFF and perform the
    normal Player-1 interaction on a genuine all-three-character object.
    Keep P1's cursor locked/casting until Hermione and Ron have both joined
    the same target. The mod observes that untouched game behavior and writes:
      [coopcast] CERTIFIED P1 cooperative class ...
    Only that observed class (and subclasses) is eligible for this map.
    An ordinary SpellTrigger, a short cast, and an unknown class are not
    eligible. If this line does not appear, the mod intentionally does nothing.

  USE AFTER CERTIFICATION:
    Turn split on. Player 2 or Player 3 aims at an instance of the certified
    class and holds Cast continuously for more than 10 seconds. Then, only while that
    hold continues, the mod invokes the real P1 SpellCursor.LockOn only when
    its reflected one-target ABI and paired no-input UnLock are safe, and
    when P1's cursor retains that target. It then places Harry, Hermione
    and Ron in the game's existing held-cast state. The object's own script
    decides what happens; the holder's normal release is the only injected
    projectile fire.

    Releasing Cast, aiming at another object, another player's normal cast,
    target deletion, map travel, F10/split shutdown, or a missing trio
    cancels the bridge and restores
    fields/states borrowed from P1 and the companions. Under [actions],
    CoopCastFallback=0 disables it. CoopCastHoldMs has a default/minimum of
    10000; it cannot be lowered into a normal short-cast shortcut.

  This deliberately reaches P1's normal controller/cursor route only after
  the strict delay and behavior proof. Test first on a reloadable save. If it
  differs from the stock P1 interaction, send hp3mod.log with the CERTIFIED
  line and the later [coopcast] lines.


V52 NATIVE AIMING (HARDWARE TESTING PENDING)
  [actions] NativeAim=1 is now the default, including existing INIs.
  Seeking uses HP3's original SpellCursorEmitter. Hovering a castable
  object uses SpellGesture: both particle textures come from the chosen
  spell's SpellIcon, and the game's function sizes the aura to the target.
  P1's own cursor is never borrowed or modified.

  Keeps the working v51 projectile/hit handlers and cast recovery. Native
  aiming uses the original 770-unit camera-relative range (v51 used 3200)
  and active-map targets, with v51's forgiving target corridor retained.
  It is not a complete reimplementation of the original player controller.

  NativeAim=0 restores the old sprite/range policy for an A/B comparison.
  GlowStyle=6 and GlowSize=36 now control only the legacy/fallback marker.
  GlowStyle=0 no longer borrows P1; it also falls back to the sprite.
  Native initialization failures fall back until the next hold.

  Cross-build and host tests pass; actual native particle visibility and
  per-pane isolation still require testing in HP3 on Windows/D3D8 hardware.
  Look for [nativeaim] bindings OK, p2 SEEK, and p2 LOCK with a spell Texture
  name and privateParticles=2. Test P1 and P2 aiming together, the Spongify
  pad and Depulso triggers, releases, F10, character changes and map travel.
  Historical controls/changelog notes below describe the older glow builds;
  this section supersedes their rendering defaults. Full research, known
  differences, and acceptance checklist are in docs/NATIVE_AIM.md.


INSTALLING
  1. Copy  d3d8.dll  and  hp3mod.ini  into the game's  system\  folder,
     next to hppoa.exe.
  2. Run the game normally.

  Windows loads a DLL from the application directory before the one in
  System32, so no other configuration is needed.

UNINSTALLING
  Delete d3d8.dll (and hp3mod.ini, hp3mod.log). Nothing else was touched.


USING IT

  >>> CHECK YOU ARE RUNNING THIS BUILD <<<
      Open system\hp3mod.log and read line 2. It must say:
          === hp3mod build v54 ...
      If it says anything earlier, or the file is missing, Windows is still
      loading an older d3d8.dll. Close the game completely before replacing
      d3d8.dll. Upgrading from v49/v50 can keep your custom hp3mod.ini; leave
      [actions] NoDip=1, CastGameplay=1 and CastAutoHit=1 (the defaults).

  >>> IF THE SPLIT FLASHES ON AND DISAPPEARS <<<
      Open hp3mod.ini and set:      StartOn=1
      The split then comes up by itself as soon as the level is running.

  Split screen starts OFF unless StartOn=1. Press F10 in game to toggle it.
  (The game binds F9 to its own screenshot command, so F10 is the toggle.)

TROUBLESHOOTING
  The split flashes on and immediately turns off again
      1. Set StartOn=1 in hp3mod.ini - this bypasses the toggle entirely.
      2. Check hp3mod.log line 2 says "build v45".
      3. Send me hp3mod.log.

  Player 2's keys also move Harry
      The mod subclasses the game window and removes player 2's keys from
      the message queue. If hp3mod.log does not contain "SUBCLASSED window",
      the hook did not install.

  The view looks squeezed / characters look skinny
      The mod sets the viewport size to the strip and preserves vertical FOV.
      If it still looks wrong, try FovScale=120 in hp3mod.ini (a bit wider)
      or FovMode=0 (raw engine FOV). Send a screenshot either way.

  A spell effect sticks to player 2 / the spell dies instantly
      Cast is hold-to-aim, release-to-fire, the projectile is not reaped.
      matching player 1. hp3mod.log should show "[spell] p1 actor flew N units".

  Nothing happens / no split
      Check that hp3mod.log appears in system\ after launching. If it does
      not, d3d8.dll is not being loaded - confirm it sits next to hppoa.exe.
  The game will not start
      Delete d3d8.dll to confirm the mod is the cause, then send hp3mod.log.
  Set [debug] Log=0 in hp3mod.ini once everything works.
